# 邮箱、AI 与局域网配置

业务配置页：启动业务服务后打开 http://127.0.0.1:4175/config 。业务环境首次启动为空数据库，只有示例店铺与邮箱，需自行添加真实账号。

邮箱支持 IMAP/SMTP 自定义主机、端口、SSL/TLS 或 STARTTLS、独立登录账号及应用授权码。AI 支持自定义 Base URL、模型 ID、Responses 或 Chat Completions 格式。密码和 Key 不回显，留空保留已保存值；更换服务地址时需重新输入授权。

保存配置不会连接外部服务。IMAP 验证仅登录后退出；SMTP 验证不发邮件；AI 验证使用固定测试文本，可能产生服务商费用。自动同步暂停，手动同步从本机业务配置页进行。发信默认限制测试收件人名单。

Windows 使用 DPAPI 保存授权。其他系统使用 AES-GCM 加密文件和当前用户可读的本机密钥；拥有同一系统账号权限的人仍可解密。数据目录、授权和访问码均禁止提交 Git。

## 局域网

先分别启动演示服务和业务服务，再执行：

```sh
npm run start:lan -- --address=<本机局域网IPv4>
```

- 演示入口：http://<本机局域网IPv4>:4180/
- 管理配置入口：http://<本机局域网IPv4>:4180/config
- 首次启动自动生成 .lan-access.json：demo 为测试访问码，admin 为独立管理访问码。不要公开此文件或把管理码群发给测试者。
- 仅监听指定地址，限制同一子网；登录有效期8小时。业务4175继续仅监听127.0.0.1。
- 管理入口只开放连接配置，不提供真实顾客/订单/邮件的读取、发信或同步接口；普通测试工作台继续使用模拟数据。
- 当前是 HTTP，授权信息只应在可信局域网填写。关闭局域网进程即停止对外提供入口。

代码保留 --with-business 选项，使用该选项会把业务工作台开放到4181。涉及真实客户数据，仅在已获授权并采取适当访问保护时使用；默认不启用。
